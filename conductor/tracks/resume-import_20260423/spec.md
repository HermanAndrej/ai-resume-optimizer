# Specification: Resume Import

**Track ID:** `resume-import_20260423`
**Type:** Feature
**Created:** 2026-04-23
**Status:** Draft

## Summary

Upload a PDF or DOCX resume, extract the text, parse it into structured profile sections via Claude, and apply the result to the profile — giving new users a one-shot way to populate the app from an existing resume instead of typing every section from scratch.

## Context

Manually filling 8 profile sections is a 30–60 minute ordeal that discourages first-time use. Nearly every user already has a resume file. Parsing it into the profile tables in ~15 seconds is the most leveraged onboarding improvement we can ship.

This track also builds `backend/services/llm_client.py` — the foundational Anthropic wrapper that every subsequent LLM-dependent track (analysis, generation, chat, validation) will use. Getting this right once avoids patching it under pressure later.

## User Story

As a new user of the resume optimizer, I want to upload my existing resume file so that my profile is pre-populated in seconds and I can jump straight to editing rather than re-typing everything by hand.

## Acceptance Criteria

- [ ] `/profile/import` page with a file upload input (accepts `.pdf`, `.docx`)
- [ ] On upload: server extracts text → sends to Claude → returns parsed structured data
- [ ] User sees a **review page** showing what was parsed, section by section, before anything is written
- [ ] User clicks **Apply** → parsed data replaces the current profile; existing rows are cleared first
- [ ] LLM call goes through the new `llm_client.py` module with prompt caching on the system prompt
- [ ] Usage (input/output tokens, cost in cents, model) is logged to `usage_log`
- [ ] Errors (invalid file type, extraction failure, LLM JSON error, auth/rate limit) surface as clear UI messages — no crashes
- [ ] After Apply, user is redirected to Personal Info with data populated
- [ ] If text extraction yields too little content (e.g., < 50 chars), surface a friendly error rather than calling the LLM with garbage

## Technical Notes

### LLM client (`backend/services/llm_client.py`)
Foundational wrapper. Used by every subsequent LLM track.

- Typed errors: `LLMError` (base), `LLMAuthError`, `LLMRateLimitError`, `LLMBudgetError`, `LLMInvalidJSONError`
- Retry: exponential backoff on rate limits (3 attempts — 1s, 2s, 4s)
- Usage logging: writes to `usage_log` on every call
- Cost calculation: `MODEL_PRICING` dict with Haiku 4.5 + Sonnet 4.6; commented "verify at https://docs.claude.com/en/docs/about-claude/pricing"
- **Prompt caching** — `cache_control={"type": "ephemeral"}` on the system block when `use_cache=True`. The parser system prompt is large and identical per call; caching repays itself within a couple of imports.

### Extraction (`backend/services/extraction.py`)
- PDF: `pdfminer.six.extract_text(io.BytesIO(bytes))`
- DOCX: `python-docx` — iterate paragraphs + tables
- `extract_text(filename, data)` dispatches by extension; raises `ValueError` for unsupported types or if result < 50 chars

### Parser (`backend/services/profile_parser.py`)
- Model: `claude-haiku-4-5-20251001` — fast, cheap, constrained extraction
- System prompt: `backend/prompts/profile_parse.py` — schema definition, "only facts present" rule, example output
- Returns a Pydantic `ParsedProfile` mapping cleanly to the profile tables

### Apply (`backend/services/profile_repo.py::apply_parsed_profile`)
- Wrap in a single transaction
- For each list section: clear then re-insert with correct `display_order`
- For `profile` row: update in place

### Route flow
1. `GET /profile/import` — upload form
2. `POST /profile/import` — file → extract → parse → render review page with parsed JSON in a hidden field
3. `POST /profile/import/apply` — validate JSON → apply → 303 redirect to `/profile/personal`

Warn on the upload page if the current profile is non-empty: "Importing will replace your current profile data."
