# Specification: Compatibility Analysis

**Track ID:** `compat-analysis_20260426`
**Type:** Feature
**Created:** 2026-04-26
**Status:** Draft

## Summary

Per-application compatibility analysis: user pastes a job description; app runs TF-IDF keyword overlap against the profile, calls Sonnet 4.6 for qualitative fit scoring, persists results to the `applications` row, and shows a results page with keyword gaps, LLM analysis, and an actionable "gap nudge" before the user moves on to resume generation.

## Context

This is build order step 5 (per `conductor/workflow.md`). It introduces the per-job workspace concept by creating the first `applications` row for each analysis. Step 6 will polish the workspace surface (CRUD, archive, etc.). Step 7 will add tailored resume generation that builds on the analysis output.

The core value: before the user invests effort in a tailored resume, they see honest, concrete feedback on their fit — so they can either skip a misaligned role or know exactly which gaps to address.

## User Story

As a tech job seeker, I want to paste a job description and instantly see how well my profile matches — what keywords I have, what I'm missing, and an LLM's qualitative read on my fit — so that I can decide whether to pursue the role and know exactly what to emphasize before generating a tailored resume.

## Acceptance Criteria

- [ ] New "Applications" link in the sidebar; lands on a list of past analyses + an "Analyze new JD" entry point.
- [ ] New-analysis form takes job_title, company, and full JD text.
- [ ] TF-IDF extracts top JD keywords; compared to flattened profile (summary + experience bullets + skills + projects + education highlights). Output: match %, matched terms, gap terms.
- [ ] LLM scoring returns structured JSON: `overall_fit_score (0–10)`, `strengths[]`, `gaps[]`, `recommendations[]`. Recommendations are ≤ 1 sentence each and actionable.
- [ ] All analysis stored as JSON in `applications.compatibility_analysis`; `profile_snapshot_hash` computed and stored (sha256 of flattened profile).
- [ ] Results page shows: overall fit score, keyword overlap (matched + missing), LLM strengths, LLM gaps, combined "Gap nudge" (keyword gaps ∪ LLM gaps with dedupe), and AI cost.
- [ ] Cost of the analysis logged in `usage_log` and shown on the results page.
- [ ] No fabrication: the LLM scoring prompt forbids suggesting any fact not anchored in the user's profile.

## Technical Notes

- **TF-IDF** via `scikit-learn`'s `TfidfVectorizer`. English stopwords, `ngram_range=(1, 2)`, `min_df=1`, capped feature count. Two-document corpus: JD vs flattened profile. Tokens lowercased; light punctuation stripping. "Match %" = `|matched| / |jd_keywords|`.
- **LLM scoring** uses Sonnet 4.6 — qualitative judgment matters. Prompt caching on the system prompt + flattened profile (largest stable repeated block).
- **Application IDs** are URL-safe random slugs (`secrets.token_urlsafe(8)`); the schema uses `TEXT PRIMARY KEY`.
- **Profile snapshot hash**: sha256 of the JSON-serialized flattened profile. Lays groundwork for the post-MVP "stale analysis" banner without adding any UI for it now.
- **No new dependencies** — `scikit-learn` is already in `requirements.txt`.
